# Checkpoint version compatibility

Read the installed task-checkpoint skill and runtime version before diagnosing a stop. Old saved instructions describe their original runtime; they cannot override the current user or restore removed behavior.

| Contract | Quota boundary | Continuation |
| --- | --- | --- |
| task-checkpoint 0.7 | Persistent automatic quota stop and preservation state | Its supported reviewed-resume procedure |
| task-checkpoint 0.8 | Save a verified handoff at the chosen remaining-usage limit, then end that run; no tool-blocking hook or persistent pause | Current explicit continuation after recovery, or a direct percentage/exhaustion choice, without a grant/review ceremony |

An explicit human stop, native permission denial, active foreign owner or uncertain external operation remains independent of quota policy. A current user may authorize a bounded read-only verification while implementation stays stopped. Verify that scope from the actual human request; if trusted cross-chat evidence is available, use it instead of requesting the same approval again. A later distinct implementation instruction must be handled as its own authority and phase.

For stale telemetry, inspect the effective selected observation and the existing collector separately. Missing, stale, future and past-reset readings are unknown. Preserve account/window identity and explicit source selection; never replace a scoped observation with another account or manufacture healthy readings. The 0.8.1 collector-selection repair uses a fresh same-account collector when project quota readings are entirely unknown or absent, while retaining current project readings and non-quota limits.

Separate source tests, installed bytes and actual native execution. Verify ordinary tools in the affected chat when authorized; a read-only project inspection alone does not prove that native check ran. Leave legitimate holds and other writers untouched. Do not restart a trial or implementation to make a verification pass.

## Reconcile context without discarding work

Start with the actual task binding, current owner, jobs and latest native instruction.
An old timestamp on a completed task is not a broken checkpoint. Verify its immutable
snapshot and current content; do not refresh every completed task just to clear an
age warning. Another chat's active or retained lease is still its lease, even if its
last turn completed or a previous handoff failed.

A runtime upgrade can change a repository fingerprint's representation. For example,
an older snapshot may omit Git index metadata that a newer collector includes. Compare
the saved and current commit, branch, remote, status and file hashes, then inspect the
actual index, staged entries and conflicts separately. A matching legacy projection
explains a representation change; it does not make new index evidence safe to ignore.
After reviewing those facts under current authority and the existing vacant task's
normal lease, save and verify a new snapshot with the current runtime. Keep the old
generation and semantic progress. Do not rewrite old fingerprints or weaken inspection.

Use each task's explicit root. A shared chat directory can belong to another task;
never rebind it or invent a second queue. An existing independently bound nested build
can be maintained only after verifying the parent's preservation boundary and current
authority. Preserve nested Git history, dirty and ignored work separately before any
new exact parent exclusion; a local exclusion alone is not a backup.

## Verify a native handoff in the right order

Read the installed Model Switcher continuation contract. Before admission, read only
the control evidence needed to establish current authority, matching checkpoint/source,
lease, jobs, quota, model selection and a completed origin with a distinct receiver.
Then claim the intent once, retire the exact native schedule, confirm retirement and
obtain the guard's execution permit. Only then run the frozen task acceptance checks,
including read-only protected-file comparisons. Read-only task work is still task work.

If a receiver performs acceptance work before retirement, preserve the failed result,
retire the schedule and cancel or reconcile that operation. Do not relabel the early
work as control evidence, replay a spent intent or release another writer. A later
authorized test needs a fresh operation after ownership and effects are reconciled.
Report configured model/effort, scheduled delivery and observed distinct-turn resume
separately; none of these is per-turn inference telemetry.
